01

Cicada · 知了↗

🇨🇳 ★ 1,478 Stars

直接监听电脑或手机允许采集的声音，生成双语实时字幕、会议记录、AI 纪要，并能把自己的发言译成对方听得见的语音。

Mac 主程序使用 Core Audio 进程级音频 Tap 捕获输出，再交给 SpeechAnalyzer 或 SFSpeechRecognizer 识别；Windows 版在源码中采用 WASAPI 回环。识别文本经过翻译后按时间轴保存，支持说话人区分、会议要点和 Markdown、Word、SRT 导出。要让会议软件听到译文，Mac 安装 BlackHole、Windows 使用 VB-Cable 虚拟麦克风。Apple 芯片 Mac 默认可在本机识别语音，但翻译或生成纪要时仍可能发送文字到外部服务；Windows、Linux、Android 的识别默认需要模型服务。Android 无法直接录制微信通话等被系统禁止采集的音频；Mac 首次打开可能被未公证签名拦截。适合跨语言视频会议、直播字幕和会后检索，不应把“本机录音”误解为全部 AI 处理离线。

Mac 与 Windows 的音频接入方式不同；跨平台隐私和模型费用需要分别配置。

02

hop↗

★ 1,529 Stars

不用制作 U 盘启动器，直接在 Windows 内部磁盘划出 Linux 安装空间与临时启动分区。

这是 Windows 图形程序与内嵌 PowerShell 安装引擎的组合。它下载或读取发行版 ISO，先检查 UEFI、GPT、Secure Boot、BitLocker 与空间条件，再缩小指定卷或利用现有空闲区域，创建 FAT32 安装分区，将 ISO 文件复制进去，并经 EFI 启动项在下一次重启时进入发行版安装程序。实际的分区与回滚流程位于 engine/Install.ps1，EFI 入口和引导配置处理在 engine/Boot.ps1；对 Ubuntu、Fedora、Arch 等启动方式分别适配。它不会代替 Linux 安装程序完成所有分区选择；FAT32 单文件 4 GB 限制、特定发行版和第二硬盘限制仍存在。全盘替换 Windows 是单独的破坏性选项，启动链或磁盘操作失败可能导致数据损失，使用前必须做好独立备份。

适合没有空闲 U 盘又确实需要原生双系统的 Windows 用户；不能把预检当成数据安全保证。

03

Disc Image Studio↗

🇨🇳 ★ 7,241 Stars

把普通图片映射成 CD、DVD 或单层蓝光刻录数据，让光盘记录面出现肉眼可见的图案。

不是给光盘封面打印图片，而是利用光盘物理编码和轨道分布制造反射明暗。它可以将图片抖动、调色与几何映射后生成 CD 的 WAV+CUE 音轨、DVD ISO 或单层 BD-R 的 ISO；支持把文件区安排在图案内圈或外圈，亦有利用刻录后的照片拟合轨距的辅助校准。BluRayImageGenerator.cs 的实际代码串联灰度图载入、二阶色调映射、通道游程映射、流式 ISO 生成及元数据保存，Windows 刻录路径则使用 IMAPI2。Windows 有图形界面，Linux/macOS 侧主要是实验性命令行。效果强烈依赖光盘、光驱固件、几何参数与写入策略；项目自己的物理模型审计仍记录部分边界和介质类型校验问题。直接刻录尚属实验性，只应使用可报废空白盘片。

适合物理媒体艺术、光盘编码研究和定制收藏盘，不是可预测成功率的商用光盘印刷方案。

04

OmniDiff↗

★ 1,111 Stars

不仅比较代码行，还能按图片像素、PDF 页面、字体字形和压缩包成员呈现真正改变的内容。

Rust 工具根据文件实际字节识别非文本格式，而不是单看扩展名；树状语法解析使用 tree-sitter，为约 25 种语言匹配语句与移动节点。二进制的差异引擎在 src/diff/content.rs 中将图片交给像素比较，将归档、字体与 PDF 拆为可命名成员，例如单独一页或一个字形。可作为 git difftool、Jujutsu 比较器、交互 TUI 或无界面 JSON/文本输出。对于前端资源、文档和代码同时变动的仓库，它比仅显示 Binary files differ 的工具更容易审查。作者公开的大规模完成率和耗时依赖其测试集合；高亮结果与人工标注并非完全一致，尤其 PDF 的人工准确率样本仅四例。公司集成时还要留意 AGPL 授权边界。

适合审查图片、字体和文档与源码混合的 Git 提交；不能把视觉差异直接当成语义正确性审查。

05

RustXNG↗

🇯🇵 ★ 846 Stars

用单个 Rust 服务聚合多家网页搜索，并通过 JSON API 和受限 MCP 接口为 AI Agent 提供结果与网页正文。

它借鉴 SearXNG 的多搜索引擎聚合方式，但本身并不维护全球网页索引。HTTP /search 支持结果、语言、域名和搜索引擎筛选；MCP 实现的 search 返回有限数量及长度的摘要，read_page 只能读取同一会话先前搜索得到的 URL，并限制正文长度、跳转目标、私网地址和 robots.txt。src/mcp/mod.rs 使用 rmcp SDK 明确提供这两个只读工具；多阶段 Dockerfile 构建 Rust 二进制、以非特权用户运行，镜像带 pdftotext 依赖。单机可用 Docker 或发行版二进制部署；JavaScript 渲染需另配浏览器工具，扫描 PDF 仍需单独 OCR。查询会发往启用的上游搜索服务，免费来源可能限流或变更，独立部署并不豁免供应商条款。适合个人检索入口及 Agent 的检索层，而非离线全网搜索。

仓库有日语文档和日文搜索配置；日本关联标记表示适配内容，不表示开发者国籍。

06

Quiet.md↗

🇨🇳 ★ 1,048 Stars

使用 Rust 原生 GPU 界面的本地富文本笔记本，以飞书 DocxXML 格式逐篇保存，兼顾搜索与可迁移性。

不同于 Electron 笔记工具，它直接用 GPUI 绘制编辑器，并把文档模型和界面分离到 crates/core 与根目录应用。crates/core/src/docxml.rs 通过 quick-xml 解析富文本块，未知节点尽可能原样保留；store.rs 将每篇笔记写成独立 XML，元信息放在 index.json，采用临时文件重命名及 .bak 索引备份。支持标题、表格、待办、代码、公式、附件、Markdown 快捷键和文档树，亦可导入飞书文档并导出 PDF/Markdown。它适合中文日常笔记及把文档保存在普通文件夹中，用 Git 或自选方式备份；并不意味着云端飞书的全部协作组件一比一兼容。尚为 Beta，部分嵌套单元格尾随空白存在已知往返限制，项目性能数字来自作者在 Apple M5 Pro 上的测量。

目前主要提供 Windows x64 与 Apple Silicon macOS 的安装包；飞书复杂文档先用副本验证。

07

pixelfx↗

★ 5,245 Stars

把 244 种像素风火焰、爆炸、法术与战斗特效实现为可运行的代码，并可导出游戏引擎使用的精灵表。

这不是只有提示词的 Skill 仓库。src/fx 目录内每个效果是独立 JavaScript 模块，src/core/fx.js 真实实现了帧缓冲、前后层、颜色与加法发光合成，以及按固定步长推进的模拟。部分特效还包含角色蓄力、命中停顿、受击与恢复的动作时间数据。网页 Canvas 可以直接调用 createFx；node tools/render.mjs 则把指定效果输出为透明 PNG sprite sheet 和逐帧 JSON，适用于 Godot、Unity、Phaser 等需要预渲染素材的工程。颜色、翻转、随机种子可按游戏风格调整，原始代码亦可改造。附带 Claude Code Skill 只是可选编辑辅助，不是特效运行的前提。限制是视觉风格偏特定像素尺寸，移植到既有角色时仍须调整动作与碰撞节奏。

适合独立游戏的 UI 动效、战斗技能和批量导出素材；直接复用代码或精灵表均可。

DSH Go↗

🇨🇳 ★ 11,394 Stars

在 Android 本机通过隔离的 Linux 环境运行 DeepSeek Harness，或者从手机连接电脑上的 Harness 会话。

Flutter 客户端整合 PRoot Ubuntu/Node 运行环境、DSH 接口和远程连接通道；app/pubspec.yaml 可核对 flutter_secure_storage、dartssh2、WebRTC、WebView 和本地客户端包。用户可以在手机查看任务、回复审批、切换模型、共享会话，并在授予无障碍权限后让本机引擎读取和操作屏幕；部分不打扰操作要求 Android 14 与 Shizuku/ADB。远程主机模式和本机引擎能力并不完全一致。安装本机环境约需 1GB 空间，省电策略可能杀后台；模型调用仍需联网及独立计费。匿名使用统计默认开启但可关闭，分享链接持有者能够查看内容。它是非官方社区客户端，不代表 DeepSeek。

适合临时在手机检查开发任务、远程批准 Agent 操作；个人主力手机开启全权限前须核查隐私。

09

WordCraft↗

★ 17,397 Stars

使用 Rust 自建 DOCX 文字处理器，既提供接近传统 Word 的图形编辑，也允许 CLI/MCP 以命令控制文档。

项目将文档模型、版式分页、OOXML 导入导出、PDF 渲染和 egui 图形界面拆为 Rust crate，并在引擎中定义统一的编辑命令。crates/mcp/src/tools.rs 不仅提供文本插入，还提供批量命令、文档结构检查、页面渲染及保存；这些与 ribbon 使用同一个命令层，因此可让 Agent 修改文件并检查结果。它适合文书批量生成、格式转换、离线编辑及研究可脚本化的办公软件。但当前仍处 Alpha：作者在差距文档中自评真实工作就绪度约 60%，复杂 DOCX 的图表/SmartArt 往返保留、分页一致性和稳定性仍是主要问题。不要直接用重要原稿测试无损往返。

有实际编辑与排版代码，不是单纯 Office 风格展示；重要 DOCX 应保留原件并比较输出。

10

RustGIS↗

★ 2,346 Stars

用 Rust 桌面程序、WebAssembly 网页版及 Python/CLI 接口处理地图、地理数据与空间分析任务。

其 GUI、数据载入、地图渲染、分析和助手功能分成多个 Rust crate；rustgis-cli 的源码提供 commands、render、run、ask 和 MCP 等真实入口，既能在编辑界面操作，也能按命令批量缓冲、裁剪、叠加图层并导出地图。输入涵盖 GeoJSON、Shapefile、GeoPackage、GeoTIFF 等矢量/栅格格式，复杂数据格式或算法可能需要已安装的 GDAL、DuckDB 或外部 GeoLibre/Whitebox 工具。应用支持 Windows/macOS/Linux，也能通过浏览器版本运行；AI 助手使用用户自选模型，只有主动调用外部模型或在线底图才会传输相应数据。项目规模庞大且较新，README 的格式覆盖和功能清单不能替代在目标数据集上逐项回归；需对坐标转换、导出图层和运算精度单独验证。

适合地图制图、空间数据初步探索和可脚本化 GIS；不能直接视为成熟 QGIS 的功能等价品。
