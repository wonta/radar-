01

Rune↗

★ 2,847 Stars

用 Rust 自绘 GPU 界面，并让编码 Agent 在无桌面环境下截图、检查控件树和模拟输入的跨平台 UI 框架。

不同于把 HTML 装入桌面壳，Rune 用 keyed element tree、Taffy 布局、Parley 文本、wgpu 批量绘制和弹簧动画组成原生渲染管线；源码中的 crates/rune/src/lib.rs 对外提供 accessibility tree、runtime、render、tooling 等接口。Agent 可以无头渲染 PNG、读取元素树再驱动交互，适合反复生成和验收桌面 UI 的编码工作流。当前是预发布框架，依赖 Git 指定提交；不同平台渲染、输入法和辅助功能的成熟度不能按正式 GUI 框架预期。

可重点试验「Agent 编写界面→截图→修正」闭环，不宜立刻替换成熟跨平台生产框架。

02

Kiri↗

★ 603 Stars

以轻量 Rust 容器守护进程和 Linux VM 替代 Docker Desktop，同时尽量兼容现有 docker CLI、Compose 与镜像。

Kiri 在 macOS/Windows 上使用小型 Linux 虚拟机，在 Linux 上直接利用内核容器能力。Docker CLI 经 Docker Engine API 对接 Kiri daemon，再通过 vsock 调度 guest agent，后者使用 clone3、namespace 和 cgroup 启动容器，不需额外 dockerd、runc 或 shim。crates/kiri/src/docker.rs 实际把常见 docker 子命令转发到 Kiri socket；docs/features.md 列明网络、端口、卷、Compose 与安全选项支持边界。相比 Docker Desktop，重点是减小中间层和常驻开销；但 Compose 兼容并非所有高级功能完全一致，Windows 仍通过 WSL2。

适合非生产容器环境的小规模替代测试；现有关键 Compose 服务先比较网络和卷行为。

03

osewa↗

★ 104 Stars

跨弱网和网络切换保持远程 Shell 的持久会话，QUIC 不通时自动改走 TLS WebSocket，并支持远程执行与端口转发。

它把 PTY、运行进程、终端状态和输出日志交给常驻 host holder，而非绑定在某条 TCP 连接上；server 只鉴权和转发。docs/PROTOCOL.md 描述了 host holder 的 Unix socket 和 Ghostty 终端快照恢复；crates/server/src/lib.rs 证实 server 以 TLS 通道与 holder 通信。客户端优先 QUIC，受限网络改走 TLS WebSocket。与 mosh 相比，它支持 TCP 回退、远程执行和端口转发；不同于 tmux+SSH，也会恢复终端画面状态。但协议仍在草案期，新增服务端端口且尚无 OpenSSH 级安全审计，不建议未经隔离直接暴露公网。

适合手机热点与 Wi-Fi 切换时运行长时编码任务；优先在专用测试账号及私有网络验证。

04

sand3d↗

★ 878 Stars

让 AI 用可阅读的短 Python 程序描述零件、装配、关节和空间坐标，再交给 Blender 生成 3D 模型。

sand3d 不自研新渲染器，而是用 Blender bpy 作几何后端，提供 profile、solid、edit、frame、joint 与 assembly 等高层接口。src/sand3d/assembly.py 定义 group、assembly、Handle 和具名锚点，方便模型先写零件再将它们组装，输出 GLB、STL、USD、URDF 等格式。比直接让 LLM 输出冗长 bpy 脚本，结构更容易阅读、复用和修正；适合机械部件概念验证、机器人结构和可程序化 3D 资产。由于依赖 Blender 的 Python 接口，开发 Python 版本受 bpy 发行版本限制，不能按普通纯 Python 轻量包部署。

项目真正价值在参数化零件关系，精密机械尺寸与碰撞仍需专业 CAD/仿真复核。

05

vork↗

★ 517 Stars

把 3D、粒子与 VFX 渲染变成无界面的 JSON 场景指令，让 Agent 直接生成预览图、视频和多通道素材。

与面向交互建模的 Blender 不同，vork 以原生 Rust GPU 渲染内核承接结构化场景，可从命令行读入 JSON，输出 MP4、MOV、PNG 或多层 EXR。crates/vork-cli/src/main.rs 中的 Render 子命令实际解析场景、通道并调用渲染管线；提供 Python/TypeScript SDK，适合 Agent 修改镜头、光线和材质后反复预览。其视频和大规模场景表现依赖指定驱动与 GPU，作者速度数据不等于所有硬件实测。项目标注为 research preview，渲染与材质兼容性仍需按场景验证。

适合程序化短片和自动生成产品演示，不是完整所见即所得建模器。

06

PrivateLM↗

★ 1,599 Stars

在一套 Flutter 客户端中切换手机本地 GGUF 推理与云端 API，离线对话与多模态聊天共用同一会话界面。

其 Flutter 服务层分离云端请求和手机端推理，lib/services/inference_android.dart 接入 llama_flutter_android 与 LiteRT LM，并处理 GGUF 模型加载、运行后端、视觉投影文件和推理生命周期。Android 可以在模型下载后本地运行；不支持的场景切换到 OpenAI、Claude、Gemini 等服务。相比只使用云端 API 的聊天套壳，区别在于真正存在设备端模型执行路径；不过不同操作系统功能并不相同，README 重点说明 Android 本地推理，而 iOS 安装另有侧载说明。模型文件、内存占用、GPU 兼容和热管理直接决定实际体验。

适合测试手机离线小模型；云端模式的请求及费用应与本地模式区分。

07

OpenHinoVoice↗

🇯🇵★ 51 Stars

用 Windows 本机语音识别把日语口述变成任意输入框中的文字，并允许再调用 AI 清除口头禅与修正标点。

这是 Rust/egui 编写的 Windows 桌面工具，语音识别依赖本地 speech.cpp 和日语 Haas 模型。src/asr.rs 创建独立子进程、通过有界队列传送 PCM、监控启动和识别超时，避免识别卡住时拖死界面；main.rs 维护录音及格式化状态。用户按快捷键录音、Enter 粘贴，快速再次按下可直接粘贴未润色的结果。词典可处理专有名词，短期历史加密保存。相比需要上传语音的听写服务，识别可留在 PC，但选择云端 AI 润色会发送文本。安装需要自行取得 speech.cpp 和模型，提供的 Windows exe 尚未代码签名。

日语办公输入很实用；先在非敏感文本和目标输入法中测试。

08

Koebumi↗

🇯🇵★ 4 Stars

在 macOS 用 Fn 键进行日语语音输入，并将口语自动调整成书面语或给 Codex/Claude Code 发语音指令。

Swift 版桌面工具支持本机 Apple 语音能力或 speech-swift 的多种 ASR 模型，Package.swift 实际依赖 Qwen3-ASR、Whisper、MLX 等模块；能根据工作目录修正文件名发音、把「スラッシュ コンパクト」转成 /compact，并口头回答 Agent 的批准提示。不同于一般听写，它兼顾日语敬语规范和编程工作流。限制是要求 Apple Silicon 与 macOS 26，未做 Apple 公证；若通过现有 Codex/Claude Code 订阅执行润色，会使用相应服务额度。

关注日语输入体验与 Agent 口述交互，不能在 Windows PC 直接运行。

09

ids-input↗

★ 7 Stars

用汉字部件描述序列（IDS）构造、搜索和编辑尚未编码的汉字，并在网页展示部件树与字形预览。

核心是无框架依赖的 JavaScript IDS 解析/序列化引擎，以及可选的 Svelte 组件和编辑工作台。src/core/ids.js 将「⿰」「⿱」等结构解析成带子节点的树并允许替换、撤销、组合；package.json 暴露 core、document、adapter、composer 等独立模块。支持汉字、喃字及西夏字的部件描述，适合古籍数字化、汉字字形教学和罕见字输入。与普通 Unicode 输入法不同，它描述的是部件结构，不保证每种组合都对应正式编码字位或标准字体字形。

对 CJK 文献处理有独特价值；需要和字形数据库及实际字体覆盖配合。
