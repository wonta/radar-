10 个项目
01

XERJ↗

★ +725 / 日

为 Agent 提供本地代码、文档和数据检索。

使用 Rust 建立本地代码、PDF、日志和结构化资料索引，让 Coding Agent 通过 MCP 查询相关文件、符号和精确行号，而非每次把整个项目读进上下文。支持 BM25 词法检索及可选的混合/向量检索，并提供兼容部分 Elasticsearch 的接口。适合多仓库知识查询；启用神经检索会增加额外模型与资源需求。

原日报中的 Token 节省幅度未经独立验证；无鉴权模式仅限可信本机。

02

Caveman↗

★ +530 / 日

压缩 Agent 的回答、日志和工具输出。

尝试通过压缩工具输出、整理多轮日志及上下文历史，减少 AI Coding Agent 阅读无效文字的成本。可以结合本地代理或不同工具环境启用处理模块，适合频繁读取长日志的工作流。压缩和去重容易遗漏关键异常行，应保留源日志并让 Agent 在需要时能回查完整证据。

原日报记载需要 Node.js 22.13+；节约比例依赖任务。

03

TokenSpeed↗

★ +25 / 日

面向高并发 Agent 工作负载的模型推理引擎。

面向多请求、高并发 Agent 场景的大模型推理引擎，研究把请求调度、模型执行和 KV Cache 管理分离，并通过可插拔算子适配不同 GPU 内核。适合研究高吞吐服务端推理与会话管理，不是普通用户一键安装的聊天程序。对具体模型架构、驱动和硬件的支持范围需要实测。

面向服务器级 GPU，不是低内存 CPU 小主机方案。

04

Octop↗

🇨🇳★ 9.5k Stars

可供多个用户使用的自托管 AI 助手。

可供多个用户访问的 AI 助手平台，通过网页控制台管理聊天、知识库、长期记忆和自动任务，并可接入消息渠道或其他代理。适合团队搭建内部助手或持续运行工具。多用户意味着需要隔离会话、文件和密钥，部署前应设置认证、存储、工具权限及后台作业资源。

Agent Teams 在原日报中标为 Beta；外部 API 推理不在本机完成。

05

Murmur↗

★ 4 Stars

为 Hermes Agent 提供跨设备图形界面。

为 Hermes Agent 增加电脑与手机都能访问的图形界面，可以管理不同角色、会话和正在执行的任务，连接已有 Hermes 运行环境或按项目提供的方式启动。适合不喜欢一直守在 CLI 前的个人用户。它主要改善操作入口，模型费用、工具权限和任务执行仍取决于底层 Hermes。

早期项目；需匹配 Hermes Agent 版本。

06

OpenChamber↗

★ 11.7k Stars

同时管理并比较多组 Coding Agent 任务。

在网页中管理多组编码 Agent 会话、GitHub 任务和代码差异，集中检查每个代理做了什么修改、是否需要人工决定下一步。适合远程服务器上有多个工作树和长期任务的开发环境。它不替代 Git 提交审查和测试；连接仓库及执行命令的权限应限制在需要的项目范围。

代码生成依赖所配置的 Agent 与模型服务。

07

Containarium↗

★ 305 Stars

给不同 Agent 分配独立 Linux 执行环境。

为 AI Agent 提供持久化、可通过 SSH 访问的独立 Linux 运行环境，避免让自动安装和执行命令直接污染用户电脑。支持 LXC/Kubernetes 后端、MCP 工具调用、GPU 透传及按租户配置的 eBPF 网络出口控制，违规连接可以留下审计记录。适合隔离运行构建、测试和服务部署；项目说明部分租户隔离与出口策略并非默认全部开启，部署时必须逐项确认安全边界。

需要适配的 Linux 虚拟化环境，并非普通单容器应用。

08

Karukan↗

🇯🇵★ 737 Stars

结合本地神经网络与词典的日语输入法。

尝试把神经网络上下文假名转汉字转换引入 Linux 与 macOS 日语输入法，分别衔接 Fcitx5 等平台输入框架。可研究连续句子转换、用户词典和传统候选排序如何结合，适合日语输入法开发者或想测试新转换算法的人。需要按系统配置输入法框架，日常使用前应检查兼容性、候选稳定性及现有词库支持。

没有 Windows 输入法版本；神经网络功能需下载模型。

09

Crescent Grove↗

🇯🇵★ 15 Stars

让虚拟角色保存连续经历与长期记忆的实验。

探索让虚拟角色不只在收到消息时回答，而是拥有随时间变化的内部状态、周期性活动和可追溯经历。通过长期记忆、状态推进和回忆机制构造持续存在感，适合研究 AI 角色与互动叙事。角色表现是模拟系统，不等于具有真实意识；持续任务会消耗模型调用和存储资源。

早期 Windows 实验，并非成熟任务平台。

10

青龙 QingLong↗

🇨🇳★ +22 / 日

用 Web 面板管理脚本和定时任务。

用网页面板集中管理定时脚本、环境变量、执行日志和通知，可以运行 JavaScript、TypeScript、Python、Shell 等任务。适合需要在家用服务器定期爬取数据、整理文件或发送提醒的用户。脚本来源和授权应检查，公网访问需配置认证；定时执行不会自动解决脚本失效与数据备份问题。

不同镜像的 crond 权限要求不同。

QuantsPlaybook↗

🇨🇳★ +20 / 日

复现量化研究报告、技术指标和组合策略。

按国内券商量化研究报告组织代码复现，覆盖择时、因子、价值和组合策略，提供数据处理、信号计算、回测和可视化示例。可研究传统技术指标与机器学习策略如何落地到代码，并比较不同假设。适合量化研究学习，不是自动盈利系统；复现依赖行情数据授权、回测参数和交易成本设置。

12

dashi-ppt-skill↗

🇨🇳★ 9.5k Stars

生成可在浏览器修改的演示文稿。

面向 AI 生成演示文稿的技能与网页版编辑器，提供多套主题、封面/目录/趋势/流程等大量版式，还能调节图表、媒体占位和页面顺序。输出既能在浏览器中继续修改，也可导出离线 HTML、PDF 与可编辑 PPTX。适合多轮修改商业汇报，复杂版式和导出时的元素位置仍需要人工逐页验收。

scientific-agent-skills↗

★ +1,091 / 日

科学研究和专业数据工具的 Agent 工作流集合。

围绕科研流程整理可复用的 AI Agent 技能，涵盖基因组学、药物发现、蛋白质组学、显微图像、临床研究及科研数据处理。各技能提供领域工作步骤、工具选择与结果整理约束，适合让模型辅助文献和实验数据工作。它不是一套统一运行的软件，相关分析仍需安装领域工具并核对科学有效性，不应用于未经授权的患者个体决策。

14

claude-plugins-official↗

★ +525 / 日

官方维护的 Claude Code 插件目录。

Anthropic 官方维护的 Claude Code 插件市场目录，集中展示可安装的命令、Skills、Agents 与 MCP 集成。开发者可以按任务选择插件，或参考官方组织方式制作自己的扩展；适合减少手动复制提示词和配置。市场包含第三方项目，安装前仍需检查来源、执行脚本、访问权限及兼容版本。

15

Ghidra↗

★ +1,366 / 日

集成反汇编、反编译和脚本扩展的程序分析平台。

美国 NSA 开源的逆向分析平台，可加载多种 CPU 架构的可执行文件并进行反汇编、反编译、函数识别、调用图和交叉引用调查。支持脚本、插件与自动分析，适合安全研究、兼容性开发和固件分析。它不会自动给出完整正确的原始源码，程序混淆、编译优化和动态行为通常需要结合调试与人工推理。

16

REA↗

★ +32,282 / 日

将逆向工程工具接入 AI Agent 的分析流程。

通过 MCP 把 Claude Code、Codex 等 AI Agent 与逆向分析工具连接起来，让智能体调查没有源代码的软件。原生程序可结合 Ghidra、Hopper 或 IDA 查看伪代码、汇编、字符串、函数调用和交叉引用；Electron/JavaScript 可追踪模块、路由、preload 与 IPC；Android APK 可结合 JADX 检查清单、类和方法；网页可观察脚本和网络请求。适合研究某个软件功能的实际实现路径，并把调查证据交给编程助手复现。需要 Node.js/npm，部分目标还要安装 JDK、JADX 或原生分析器；工具不会自动恢复完整源码。

17

VoiceStudio↗

★ +3,027 / 日

本地语音克隆、配音与有声书制作工作台。

提供本地语音克隆与声音创作工作台，把说话人样本、文本配音、转录和音频/视频配音任务集中管理。支持长文本分段、有声书制作、批量转换及本地 API，适合视频作者和播客后期。模型、语种和音质依具体语音引擎而异，克隆他人声音应取得授权，GPU 性能也会影响生成速度。

context-mode↗

★ +902 / 日

减少 Coding Agent 的工具输出占用并保留工作历史。

通过 MCP 和 Agent 生命周期 Hook 处理大量终端日志、文件内容和网页抓取结果，先压缩或索引输出，再从 SQLite 保存的历史中按需找回相关片段。适合长期 Coding Agent 会话，减少一次工具调用就塞满上下文窗口的情况。需要按工具与模型配置钩子；压缩会损失细节，应保留回看原始证据的路径。

ECC↗

为 Coding Agent 提供开发、记忆和安全工作流。

围绕 Claude Code、Codex 和 OpenCode 整理一套工程化代理约定，包括任务分解、代码审查、测试验证、上下文记忆、安全检查和重复工作自动化。更像可选的实践模板库，而不是新的 AI 模型或推理引擎。适合把团队常用规范放进 Agent 工作流，具体规则要按项目大小和团队习惯裁剪。

superpowers↗

以可安装的 Agent Skills 组织软件开发流程，强调先澄清需求、提出设计，再做实现计划、测试与代码检查，避免直接让模型从一句提示开始乱改代码。适合把反复使用的工程实践固定成一致的工作方法。它改善的是 Agent 的步骤约束，不是新的模型能力；项目需要自行保证测试运行及审查质量。

多 Agent 协作、任务编排与记忆系统。

提供多 Agent 协作、任务分配与记忆组件，研究多个角色怎样共享上下文、协调执行以及在一个项目中汇总结果。适合需要并行调研、编码、测试或长期工作流的用户。真实效率受模型、调度策略和工具可靠性影响，部署前应确认所需服务、权限和持久化配置。
