cloudflare/security-audit-skill

★ 36,262 Stars

将安全审计拆成覆盖记录、独立漏洞验证和可追溯报告，而非一次性 Agent 扫码。

把代码安全审计拆成可追踪的阶段：先了解系统架构和审查范围，再登记检查覆盖，最后单独验证可疑问题并生成有证据的报告。使用 architecture.md、coverage-ledger.json 与 findings.json 区分已检查、待确认和已否定的结论，适合约束安全审计 Agent 不要直接把猜测当漏洞。最终风险判断仍要人工复核。

stablyai/orca

★ 101,173 Stars

Orca｜隔离 Git worktree 并排运行 Codex、Claude Code 等 Agent，统一审阅改动。

让多套 Codex、Claude Code、OpenCode 等编码 Agent 在独立 Git worktree 里并排工作，通过桌面界面查看终端、差异和任务进展，还能从手机跟进。适合让不同模型并行尝试实现方法，再集中选择、审查和合并。代理订阅、执行费用、权限和跨分支冲突仍由使用者管理。

snapotter-hq/SnapOtter

★ 2,830 Stars

一站式自托管 PDF、音视频和图片转换、OCR、批处理流水线。

将 PDF、图片、音频、视频转换和 OCR 功能集合到一个网页控制台，支持批量文件与流水线处理，也提供 REST API 给自动化工具调用。适合家庭服务器或团队集中做格式处理；项目提供容器快速启动，但生产环境推荐独立数据库与队列。首登要修改默认管理员密码，部分 AI 加工能力可能需要 GPU。

koyasi777/mozkey

★ 517 Stars

Mozkey｜日本 Mozc 分支：加入本地 Zenz 纠错、文脉转换及扩展日语词典。

基于日本 Mozc 输入法改造，加入本地 Zenz 纠错、上下文候选和词典扩展，目标是改善长句输入与假名转汉字准确率。适合日语重度输入用户测试更贴合语境的候选选择。Windows 安装包未签名，macOS 主要为开发构建，Linux 扩展支持尚未充分验证；替换系统输入法前应备份用户词典。

xiaofang142/hivemtk

★ 131 Stars

HiveMtk｜中文营销 SCRM：社媒收件箱、客户信息、RAG 检索及 ReAct 智能体。

面向社媒获客和客户跟进的中文 SCRM 平台，把不同渠道会话、客户画像、RAG 搜索与 ReAct Agent 放在一个工作流中。技术上采用 Go/Vue、PostgreSQL/pgvector，部分渠道通过浏览器扩展桥接。适合研究业务线索管理自动化；不同平台的登录、消息权限和风控政策会限制可用性，商用改造还需核对 AGPL。

eagle-hq/EAGLE-4

★ 715 Stars

EAGLE-4｜随批量与设备自适应的推理投机解码，动态配置草稿 Token。

研究大模型投机解码：先由较小的 draft model 预测候选 Token，再交由目标模型验证，以减少生成延迟。项目根据批量大小和设备情况动态调节候选数量，主要展示服务器 GPU 工作负载。它不是新的通用聊天模型，对家用显卡的收益没有直接保证，仓库许可也包含不同于常见 OSI 开源协议的限制。

7

ly05010419/MacNativeGames

★ 3,825 Stars

原生运行自有 Switch 游戏资源的 Apple Silicon 适配工程，不是传统模拟器。

研究把自己持有的 Nintendo Switch 游戏资源转换为可在 Apple Silicon 设备上原生执行的程序，不是传统的逐条指令模拟器。涉及 ARM64 代码适配、Switch 服务接口替代和 Metal 图形映射，目标是减少模拟开销；需要自行准备有权使用的游戏文件和密钥。不同游戏的系统调用、图形兼容和设备支持程度不一，不能视为完整 Switch 游戏兼容层。

VictorTaelin/uniichat

★ 551 Stars

UniiChat｜单一长期 AI 对话，以可递归展开的摘要二叉树保存可追溯历史。

以单个长期 AI 对话为核心，使用可递归展开的摘要树保存历史：平时只让模型阅读相关概要，需要时追溯到原始消息，避免每轮都塞入整个聊天记录。支持自行部署和连接 API、Shell、子 Agent，适合研究长期上下文管理。作者提醒较多代码由 AI 生成，导入敏感历史前应检查安全与稳定性。

Kandev｜可自托管的 Agent 看板与审查台，支持 worktree、Docker、SSH。
