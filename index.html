01

phoneuse↗

★ 535 Stars

通过 AirPlay 接收 iPhone 屏幕，再以蓝牙 HID 回传点击和文字，让 Linux 上的 AI Agent 操作未越狱的 iPhone。

项目把两条原生能力组合成可自动化控制链：UxPlay/GStreamer 在 Linux 电脑上接收 iPhone 的屏幕镜像，蓝牙鼠标键盘或可选 ESP32 桥接板将点击、拖动和键盘输入送回手机；phoneuse/mcp_server.py 又把截图、可点击文字定位和操作命令暴露为 MCP 工具。手机端不需要安装 App 或越狱，PC 与手机须在同一网络，iPhone 要打开屏幕镜像及辅助触控。安装脚本会关闭 Linux 蓝牙服务的输入插件，可能影响电脑原有的蓝牙键鼠。作者只在一套 iPhone 17 Pro、Arch Linux、Hyprland 环境验证，其他机型及桌面环境尚不能视为兼容。

02

Agent-VScreen↗

🇨🇳★ 45 Stars

为现有 Android AI Agent 提供不占用主屏幕的虚拟副屏，通过 CLI、MCP 或 HTTP 在后台操作应用。

Kotlin 应用调用 Shizuku UserService 创建由 shell 身份持有的虚拟显示，解决普通应用创建的显示无法启动其他应用的问题；VScreenDisplayService.kt 实现显示与输入控制，api/Mcp.kt 提供单个 vscreen MCP 工具，返回操作结果、画面和可点击元素。自带本地 OCR、条件等待、步骤复核、应用禁用/只读规则和可随时接管的悬浮预览；它本身不包含大模型，需对接已有 Agent。要求 ARM64 Android 11 及以上并启用 Shizuku，远程控制需要额外的 Tailscale 或端口转发。访问令牌相当于手机操作权限，不应公开。

03

myco↗

🇨🇳★ 59 Stars

用一个自建 Hub 连接多台设备上的 Codex、Claude Code 与其他命令行 Agent，实现派单、回执和远程命令。

Go 项目把 Hub、CLI 和后台 Runner 做成同一套程序：Hub 用 SQLite 存储节点、收件箱、权限和回执，Runner 通过出站 HTTPS 长轮询拉取任务，续接各自 Agent 原有会话，并把进度和结果回送。internal/runner/runner.go 实现轮询、超时及繁忙会话处理，前端能查看设备与任务；可用标签广播任务，或授权特定 Agent 通过 shell 节点执行远程命令。适合多台电脑和 VPS 协作，不必在被控机器开放入站端口。远程 shell 以本机用户权限执行而非沙箱，务必限制允许的发送者；原生 MCP 端点和团队权限仍在项目路线图中。

PLaMo Translate Desktop↗

🇯🇵★ 112 Stars

把日本 PLaMo 翻译模型运行在自己的电脑上，离线翻译文本与网页，并支持术语表和日语敬体选择。

采用 Rust GPUI 桌面界面、llama.cpp 推理后端和 PFML 提示构造器，模型可选择不同体积的 GGUF 量化版本。crates/engine/src/document.rs 负责长文分段、前文译文历史延续与重复输出回退；Chrome/Edge 扩展可调用本机 Native Messaging Host 翻译整页，也可独立用浏览器 WebAssembly/WebGPU 执行小模型。首次需要下载模型，之后可离线使用，支持日英互译及其他语言。较大模型的内存和算力需求明显，浏览器独立模式限制为较小模型；代码许可证与模型的 PLaMo Community License 分开，使用前需分别确认。

05

IPVIO Stream↗

★ 307 Stars

面向 Android TV 和 Fire TV 的开源 IPTV 播放器，支持自备 M3U、Xtream 与 Stalker 播放列表。

Android Kotlin/Jetpack Compose 界面围绕电视遥控器设计，播放器采用 Media3/ExoPlayer，提供多播放列表切换、直播节目表、收藏、家长控制和电影剧集元数据展示。源码 LiveTimeshift.kt 实现可配置的本地时移缓冲与直播回退，另有录制、断流重连、音轨/字幕选择与续播功能；可选的 TMDB、OMDb 密钥用于补全资料而非提供节目。APK 可安装在 Android TV、Google TV、Fire TV，但项目完全不附带频道、影片或账号，必须使用自己有权访问的信号源。实际播放兼容性取决于媒体格式、设备解码能力与来源服务器。

Mister Download Manager↗

★ 3,887 Stars

用 Rust 实现跨平台下载管理器，提供动态分段、断点续传、种子下载与浏览器接管。

Rust workspace 包含独立下载引擎、桌面界面、Torrent 模块和浏览器扩展。crates/engine/src/planner.rs 根据剩余区间、连接占用状态与最小分段阈值动态分配任务，并区分已领取与已写入字节，减少并发下载时重复写入风险；支持 HTTP 下载恢复、任务管理及多种代理配置。Windows 和 Linux 有安装包，macOS 仍标为实验版本，Chrome/Firefox 扩展可将网页下载交给本地程序。README 的速度对比由项目作者自行测量，不能推定所有网站都优于 IDM；未签名安装包、浏览器接管和文件写入权限应在测试环境先确认。

iCopy↗

★ 97 Stars

直接从 iCloud 下载照片原件到 Windows 电脑或外接硬盘，逐个校验并在断线后继续备份。

程序以 Rust 处理并发下载、SQLite WAL 状态登记和本地文件验证；使用一个封装 pyicloud_ipd 的 Python 桥接进程完成 Apple 登录、双因素验证及下载链接续期。icopia/src/verificar.rs 依据文件大小、JPEG/HEIC/视频容器结构和重新读取的 SHA-256 校验原件，写入临时 .part 文件，确认完整后才改名。支持 Live Photo 的视频部分、按年月整理和自动周期同步。另设需要明确确认的云端清理功能，操作前会再次核对本地副本并排除最近30天项目；涉及云端删除，首次使用应仅启用下载且保留独立备份。当前面向 Windows 10/11。

Hermes Voice↗

★ 618 Stars

通过 Home Assistant Assist 把旧款 Amazon Echo / Echo Show 改造成 Hermes Agent 语音终端。

系统沿用 echo-dot-assist 的音频输入输出和 Home Assistant 的语音识别、语音合成链路，再由 custom_components/hermes_voice/conversation.py 把每次对话发往指定 Hermes Agent 配置，保留会话标识并流式返回语音文本。Echo Show 还能展示听写、工具调用、回答过程与后台任务；项目提供自定义屏幕、唤醒词和可选摄像头组件。需要已有 Hermes、Home Assistant、已被解锁的兼容 Echo 及相应的 STT/TTS 服务。README 特别提示必须核对型号和 Fire OS 固件，较新固件可能阻止解锁，刷机有变砖风险；自动安装 Skill 目前受 Hermes 安全扫描阻拦，应采用手动安装而非关闭扫描。

CHIMERA↗

★ 1,182 Stars

在浏览器中用物理声道模型实时合成说话、歌唱、节奏和动物鸣叫，而不是播放预录语音样本。

Rust 引擎把肺部气流、声带/鸣管、口腔与鼻腔的物理模型串联为发声管线，构建为 WebAssembly 后在 AudioWorklet 中运行。crates/chimera/src/lib.rs 可看到声源、声道、发音器官、音素规划和声学分析模块；页面允许拖动舌头、嘴唇与下颌，输入英文/IPA 生成发音动作，也提供带歌词的钢琴卷帘、节奏音色和鸟类等非人声模式。适合交互声学实验及原创音效原型，不依赖云端语音模型。开发需要 Rust WASM 目标与 Bun，浏览器工作线程要求 localhost 或 HTTPS 的安全上下文；音质是物理建模模拟而非真人录音复刻。

S2Arm↗

🇨🇳★ 1,728 Stars

尝试将用户自有的 Nintendo Switch ARM64 游戏重写为 iPhone、iPad 与 Apple Silicon Mac 原生可执行程序。

项目采用构建时指令重写而不是运行时 CPU 模拟：runtime/rewriter/rewriter.c 处理 ARM64 游戏代码转换，graphics/metal 与 translator/ 负责图形兼容层，shell/ 与打包工具提供统一游戏库。Mac/Windows 启动器用于导入游戏文件、更新和密钥，构建、签名后安装到 Apple 设备；还暴露 s2armctl 便于 Agent 读取进度与故障。README 列举了游戏兼容率和测试数据，但这属于维护者自述，不是本次独立实机验证。只针对64位游戏，且不附带游戏文件或密钥；需要合法获取的自有游戏、设备签名条件，项目仍存在兼容性和升级存档风险。

PrivacyProbe↗

🇨🇳★ 76 Stars

在已 Root 的 Android 手机上审计应用对相机、麦克风、定位和网络域名的访问记录。

应用通过 root 读取 dumpsys、logcat 与 /proc 信息，再由 native/privd.c 的原生守护程序配合 AF_PACKET、tracefs uprobe/kprobe 采集 DNS、进程及设备访问事件。事件经 UID/PID 关联到应用，按日写入本地 SQLite，并按调用者或目标生成时间线；支持 CSV/JSONL 导出与自检。它只读采集，不主动注入目标 App；需要 Android 12 以上 ARM64 和 Magisk/KernelSU root。作者主要在 Xiaomi 17 Pro Max 的 HyperOS 环境适配，不同厂商内核和 SELinux 可能导致漏报；DoH/DoT、部分 QUIC 流量及服务代理的准确归因仍有限制。

Aspen↗

★ 96 Stars

面向大量编码 Agent 并发提交的自建 Git 服务，把 Git 对象包放在对象存储中、分支版本放在数据库里。

Aspen 保留普通 Git 的 HTTP/SSH 协议，却改变服务端存储与并发模型：Git pack 被验证后直接作为不可变对象保存，分支版本则按独立链表写入 PostgreSQL/SQLite，避免一个仓库范围的全局推送锁。crates/aspen-meta/src/push.rs 实现按 ref 的提交事务与冲突处理，其他模块负责对象存储、拉取规划、后台 pack 合并及缓存。适合研究多 Agent 高频 push/fetch 的基础设施架构；README 明确标记为 pre-alpha，尚无正式 Release，数据格式还可能变化，不适合作为唯一生产代码仓库。

13

satmux↗

★ 1,006 Stars

在高延迟卫星 Wi-Fi 上复用多条常驻 TCP 通道，降低远端服务请求的握手开销。

单文件 Python 程序在本机提供 SOCKS5、HTTP CONNECT 和代理请求接口，在远端 Linux 节点维持多条预热 TCP 连接，按近期传输负载分配新请求；satmux.py 同时实现握手优化、zlib 压缩、请求帧和连接重建。作者在高延迟机上网络环境做过对比测试，所报告的加速不应外推至普通宽带或不同卫星运营商。需要自行部署地面服务器并配置 PSK，属于面向特定链路的实验工具。部分请求模式使用自定义 BLAKE2b 密钥流和 HMAC 组合而非现成成熟隧道协议，处理敏感流量前应单独评估其安全性。

14

灵录 Capwise↗

🇨🇳★ 82 Stars

在原生 macOS 编辑器里一站式完成录屏、字幕校对、双语翻译、封面生成和 AI 辅助剪辑。

项目基于 Cap 的录制和媒体组件，桌面工作区使用 Rust + GPUI；apps/desktop-gpui/src/editor_assistant.rs 定义可审阅的 JSON 编辑操作，支持字幕字词修改、指定区间裁剪、镜头缩放和音轨增益等，操作前先显示方案并可撤销。录制与普通编辑本地完成，AI 校对、翻译和生成封面通过用户选择的云端模型服务或本地 ACP 助手接入。适合教程、产品演示和双语短视频制作；当前验证的安装包仅面向 Apple Silicon macOS 13.3 以上，Intel/Windows/Linux 尚无验证版。云端识别会发送音频，剪辑模型会读取相关字幕上下文。

15

HALO↗

★ 285 Stars

Apple 研究项目：从仿真生成仿人机器人动作，并把语言目标拆成可执行的机器人子任务。

仓库分为仿真数据生成、动作生成器、运动跟踪策略、任务编排及闭环系统五部分，支持 Isaac Lab/MuJoCo 仿真和 Unitree G1 部署研究。orchestrator/README.md 说明用本地视觉语言模型结合机器人视角图像规划 go_to、push、sit 等子任务，system/halo_system/nodes/orchestrator_zmq.py 接收图像及状态并决定继续、重试或切换动作。适合机器人学习、仿真到实体迁移和多阶段任务编排研究，不是普通 PC 即装即用的聊天 Agent；训练与实时运行需要匹配的仿真环境和机器人硬件，编排器示例还要求大内存 Apple Silicon 上加载较大的本地模型。
