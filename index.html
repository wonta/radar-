Mika↗

🇨🇳★ 6,601 Stars

在 Android 手机的独立后台屏幕中操作应用和网页，让 AI 按步骤完成查找、点击、输入及整理任务。

采用 Android 原生应用与无线调试配对，在独立的后台显示环境中读取界面、识别控件并执行点击、滑动、输入；用户可以继续操作主屏幕，还能随时查看任务画面。任务可涉及聊天记录整理、网页信息查找和多步应用操作，并由自带浏览器承担网页任务。应用本身支持 Android 11 起，但真正操作其他手机应用需要 Android 12 或更新版本，首次配置涉及开发者选项和无线调试。模型通过用户选择的 API 或账号接入，不能把“本机操作”理解为模型也完全离线；敏感消息、账户授权和支付环节仍需人工把关。

agent-autoloop↗

🇨🇳★ 2,420 Stars

给 Claude Code、Codex 等命令行 Agent 增加持续接单、任务续跑和人工审批功能，而不必一直守着终端。

系统把定时触发、GitHub Webhook 和业务事件转成任务，再按规则派给 CLI Agent。kernel/rules.ts 定义事件匹配与并发分组，worker/worker.ts 负责启动独立进程、保存进度和恢复回执；飞书、钉钉及桌面通知等通道可以发送需要人作决定的卡片。等待审批时 Agent 进程退出，决策记录保存在持久化状态中，回复后继续原会话。适合持续巡检、Issue 处理和自动交付流程；目前主要面向 macOS/Linux，需要 Node 24、Git 和已配置的 Agent，模型额度仍由相应账户承担。

dsh-superagent-prototype↗

🇨🇳★ 18,516 Stars

DeepSeek 团队公开的自主编码 Agent 研究原型，围绕工单、权限与会话管理自动推进 GitHub 开发任务。

这是与 DeepSeek Harness 配合使用的单仓库编码 Agent 原型，不是可直接购买或投入生产的完整产品。它监听被授权的 GitHub 事件，也可接入飞书，把需求形成工单，分配独立任务会话和工作目录，在原讨论线程中反馈成果或 Pull Request。src/core/engine.ts 将事件接收、评估、任务分配、回复和状态变更置于事务化的领域入口，另有人工决策面板。适合研究多轮 Agent 自治及授权边界；README 明确提示代码仍属研究性质，公开版也不等同团队内部实现。

floci↗

★ 29,551 Stars

在本机模拟 S3、Lambda、DynamoDB 等 AWS 服务，方便离线开发、集成测试和 CI 验证。

以 Java 和 Quarkus 实现兼容 AWS SDK/CLI 的 HTTP 接口，常用服务可统一指向 localhost:4566；S3、DynamoDB 等由内部存储后端处理，Lambda、RDS、ElastiCache 等部分服务通过真实 Docker 容器提高协议与运行环境的贴近程度。提供 CLI、独立原生二进制及 Docker Compose 部署途径，现有应用通常通过替换 endpoint 即可接入。适合无需真实云资源的自动化测试、Terraform 预演和离线调试；它不能覆盖全部 AWS 行为，Compose 还映射多个端口并挂载 Docker socket，运行时需要注意隔离权限。

worktrunk↗

★ 10,991 Stars

用简化命令管理 Git worktree，让多个编码 Agent 分别在独立工作目录里并行修改同一仓库。

Rust 编写的 wt 命令将创建、切换、列出、合并与删除 worktree 组织成面向分支的操作，例如 wt switch -c -x claude feat 能建立新工作区并启动 Agent。除基础 Git worktree 封装外，还包含 Git 钩子、合并流程、交互选择器、差异生成提交说明和构建缓存复用等机制；Cargo.toml 和 src/main.rs 可对应到 CLI 及功能模块。适合同时运行 Claude Code、Codex 等编码任务以减少文件冲突；它不负责模型推理，也不自动消除跨分支的语义冲突，最终合并仍需要测试和审查。

Pi-Remote↗

★ 295 Stars

把本机 pi 编码 Agent 的终端会话实时映射到手机浏览器，支持远程查看、回复和切换模型。

项目通过 pi 的扩展接口读取终端事件，并由 extension/pi-remote-sync.ts 将消息、工具调用与会话状态同步给 Node relay；手机或桌面 Web UI 再转发新消息、任务控制、模型与思考级别切换等操作。Relay 可在自己电脑上运行，也支持局域网访问和按需启用隧道，设备连接采用配对令牌与连接窗口限制。与一般远程桌面不同，Agent 及工作文件始终留在原机器。它专为 pi 编码 Agent 开发，不会自动控制 Codex 或 Claude Code；远程控制凭据需要妥善保护，当前主要面向个人单用户使用。

07

kanzo↗

★ 1,008 Stars

将轻量看板和 MCP 服务打包进一个 Rust 程序，让人和多个编码 Agent 共用任务进度。

启动 kanzo 就能在浏览器打开本地任务板；同一可执行程序也通过 kanzo mcp 或 HTTP MCP 接口向 Agent 提供读取、创建、认领、移动卡片和评论的工具。src/main.rs 明确实现本地服务、项目同步、共享及导出命令，src/mcp.rs 将任务操作封装为工具并尽量缩短返回文本；数据保存在本地目录，还可以通过 Git 同步或局域网共享给其他设备。适合同时管理多个项目的自动编码任务。其设计以个人使用为中心，局域网共享不能当作具备企业级多用户权限和审计的协作系统。

astrbot-for-android↗

🇨🇳★ 327 Stars

在无需 Root 的 ARM64 Android 手机上直接部署 AstrBot 与 NapCat，作为可随身运行的聊天机器人主机。

原生 Kotlin/Jetpack Compose 管理界面负责服务启停、资源监控、日志、备份恢复和更新，机器人程序则在 APK 附带的 PRoot Ubuntu 环境中运行，内置 WebView 可访问 AstrBot 与 NapCat 的管理后台。QQ 消息通过 OneBot 对接 AstrBot，再转给用户配置的模型；可选局域网 WebUI、SSH、Shizuku 辅助以及后台运行设置。适合把备用手机用于个人机器人实验，但完整 APK 约 1 GiB，且后台进程容易受 Android 省电策略限制；QQ 登录、模型调用仍需要网络与相关账户。

Scrapling↗

★ 96,435 Stars

把网页请求、浏览器渲染、数据解析和并发爬取整合进同一套 Python 工具，并提供 MCP 接口。

静态页面可走 HTTP 请求，动态页面可切换浏览器会话，CSS/XPath 与文本规则负责提取字段；scrapling/spiders/engine.py 结合调度器、会话管理器、并发限制、自动节流、重试与检查点实现完整爬虫流程。抓取结果可导出 JSON/CSV 等格式，也能转成适合检索或大模型处理的 Markdown，并向 Agent 提供 MCP 工具。适合构建商品监控、资讯采集和研究语料流水线；浏览器模式比纯 HTTP 更消耗资源，部署需要对应依赖，爬取还须遵守目标网站访问限制与法律要求。

auto-ontology↗

★ 4,798 Stars

自动从数据库生成业务语义关系图，让 AI 依据统一指标定义执行可复查的自然语言 SQL 查询。

项目先扫描数据表、字段样本和主外键关系，再建立业务术语、可复用 SQL 属性及表间连接，并将语义目录保存到 Postgres/pgvector。管理人员可以审核、补充或认证概念；问答代理从语义图检索候选对象，检查过滤条件、生成 SQL 并展示查询依据，MCP 和 Web UI 方便其他 Agent 或分析人员接入。Docker Compose 同时编排数据库、数据摄取服务、后端、前端及迁移任务。适合内部数据库跨表分析，但仍需模型 API 与数据库凭据，自动推断的字段含义和查询权限必须经人核实。

Haas-ASR↗

🇯🇵★ 35 Stars

面向日语音频的可本地部署语音识别推理程序，支持长录音切分及专有名词词汇表。

Haas-ja-v1.0 采用 FastConformer 编码器及带 Kimi Delta Attention 预测网络的 TDT 解码器，依赖 NVIDIA NeMo。代码中的 longform.py 会在约 30 秒目标点附近寻找低能量窗口切分，再分批转写，减少在词中间截断造成的识别问题；另外可对专业词、姓名或产品名施加词汇表增强，并结合其他模型实现说话人标记。README 报告在日语基准上的加权严格字符错误率约 6.12%，属于项目评测结果。运行需要 Linux、NVIDIA CUDA/Triton GPU，不能直接在纯 CPU 小主机或 macOS 上运行。

totk-pc-recomp↗

★ 4,826 Stars

把《塞尔达传说：王国之泪》的 ARM64 游戏代码静态重编译为 Windows/Linux 原生 x86-64 程序。

它不是运行 Switch 模拟器，而是从用户持有的游戏文件提取模块，将 ARM64 指令提升为 C，再使用本机编译工具链生成 x86-64 可执行代码；docs/architecture.md 具体说明了指令重编译、系统调用替代及 NVN 到 Vulkan 图形后端的实现。项目还提供窗口分辨率、帧率、手柄和部分模组支持，Windows/Linux 都是目标平台。仓库不提供任何游戏文件，使用者必须自行合法取得原版游戏及对应更新；仍处早期开发阶段，可能出现画面问题或崩溃，安装时需要较大磁盘空间和 Vulkan 1.3 显卡支持。

nv-uefi-unlocker↗

🇨🇳★ 1,735 Stars

在操作系统驱动启动前尝试解除部分 NVIDIA 显卡的张量计算限制，面向特定 RTX/GTX 架构实验。

项目以 Rust 实现 UEFI 引导程序，在系统启动前检查 PCI 设备、GPU 固件状态及适用路径，按需执行预驱动事务，随后继续引导 Windows 或 Linux；loader/src/main.rs 包含确认流程、日志、失败处理及 chainload 入口。作者提供了 RTX 20/30/40 系列的兼容与性能测试记录，宣称部分张量精度负载可获得提升，但这些结果不能直接推广到全部型号、驱动和游戏。该工具涉及显卡底层初始化和固件交互，存在启动失败、兼容性及稳定性风险；不应把它当作通用 FPS 优化工具或已验证适配所有 RTX 3060 的方案。

claude-mem↗

★ 112,778 Stars

记录编码 Agent 的工具操作和项目决策，跨会话压缩、搜索并恢复相关上下文。

系统通过 Claude Code 等客户端的生命周期钩子收集操作观察及会话概要，由 Bun 管理的服务写入 SQLite，并配合向量搜索实现关键词与语义混合检索。Agent 可通过 MCP 先搜简短索引，再请求时间线与完整观察，从而避免每次载入全部历史记录；也提供 Web 查看界面与上下文注入机制。适合长期维护代码库、跨会话查找曾做的修改。项目当前安装文档同时包含账号登录、托管 observer 试用及本地模式说明，必须确认实际启用的存储与模型处理方式，不能直接假定所有内容仅留在本机。

pr-agent↗

★ 14,710 Stars

在 GitHub、GitLab 等代码托管平台自动审查 Pull Request、提出修改建议并回答代码差异问题。

Python 项目通过各平台的 Git Provider 适配器获取 PR 差异、上下文与评论，pr_agent/agent/pr_agent.py 将审查、改进建议、生成描述等指令分派给对应工具，模型调用由 LiteLLM 等后端处理。既可在 GitHub Actions 中触发，也可通过本地 CLI、Docker 或 Webhook 部署，适合团队把初步代码审查接入已有 CI。该仓库属于社区维护的开源 PR-Agent，与 Qodo 当前商业产品不同；使用者需提供模型 API 凭据，自动建议仍须人工复核，而且部分文档问答命令因凭据暴露问题暂被禁用。

MoneyPrinterTurbo↗

🇨🇳★ 138,894 Stars

将主题或关键词转换成视频脚本、配音、素材、字幕及成片的可自动化短视频生产流水线。

Python 的任务管线将文案生成、图片或视频素材搜索、语音合成、字幕处理、背景音乐及最终视频拼接串联起来，app/services/task.py 可见任务状态、并行处理和发布队列逻辑。提供 WebUI、API、CLI 和 Agent 多种入口，可在 Windows/macOS/Linux 上运行，也有 Docker Compose 与预构建镜像。适合批量制作资讯讲解、商品介绍或多语言短视频的原型。虽然编辑流程可自托管，所调用的大模型、音视频生成及部分素材服务仍可能按量计费；生成内容、配乐素材及自动发布必须自行核查质量、版权和平台规定。

phone-harness↗

★ 649 Stars

通过 MCP 给 AI Agent 提供可操作的云端真实 iPhone 或 Android 模拟器，用于移动端自动化测试。

Python MCP 服务封装云端设备列表、创建/结束会话、获取界面元素、截图、点击、滑动、输入及应用控制等操作，src/phone_harness_mcp/server.py 要求每次调用显式传入设备 ID，避免误操作到其他会话。它用 Streamable HTTP 与 OAuth/令牌授权接入 Claude、Codex 等 MCP 客户端，特别适合复现移动端 UI 流程、检查发布后的实际操作。这里控制的是服务商托管设备，并不会直接接管用户自己手里的手机；云端 Android 和真实 iPhone 分别有计时或订阅费用，测试账号与敏感数据需谨慎处理。

OpenTV-Remote↗

★ 187 Stars

让 Android 或 iPhone 充当可自定义布局的智能电视遥控器，按电视协议显示相应控制按钮。

Android 端使用 Kotlin/Jetpack Compose，iPhone 端使用 SwiftUI，支持通过局域网发现设备、保存电视、按厂商或协议能力展示方向键、音量、频道、文本输入及应用快捷按钮，并允许自定义按键网格、颜色和左右手布局。仓库分别维护 Android、iOS 原生工程，并用共享测试夹具对照两端界面行为；已描述的协议包括 Android TV Remote v2、三星 Tizen WebSocket、LG SSAP 和部分蓝牙 HID。适合替换丢失的物理遥控器，但不同电视的配对、指针和输入功能并不完全一致，作者也明确不保证所有机型真实兼容。
