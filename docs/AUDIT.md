# radar 重构审计｜2026-10-16

## 范围和基线

目标：保留现有私人仓库和 Vercel `radar` 项目，把不完整的单页样机重建为可阅读、可追溯的归档网站。

旧 main 基线：`ec31d1180a8eef8f5f502168ce36afa83059b3dc`。检查了 README、入口、样式、应用代码、历史数据与 CI。没有修改同账户下另外一个 `github-radar-wonta` 项目。

## 参考站点

实际读取了 [HelloGitHub](https://hellogithub.com)、[GitHub Trending](https://github.com/trending)、[Product Hunt](https://www.producthunt.com) 的公开页面内容与信息结构。借鉴项目列表、分期入口、短介绍和直接仓库链接，不复制品牌及图片。LibHunt 页面读取失败，未将其写为已完成研究。

本工作容器的 Chromium 受 URLBlocklist 管理，所有 URL 导航均受阻；未关闭或修改该策略。外部参考网站的可视化截图未完成。新版本地截图通过加载本地源码进行渲染，不是生成式效果图。

## 数据恢复说明

原日报以具体日期为准；项目名与总数量没有补齐“每日固定数量”。10/12 的部分入口原先是不可恢复的对话引用，本次依据项目名、用途与上游仓库确认后补入具体仓库地址，包括 Folia、Anatomy、Repowise、omdrop-owl、DigUp、OSS Scanner、Mailcheap、Photo Frame Dashboard、AI Homepage、Craft Launcher 和 Pi Durable Assistant。

历史数字异常与上游当前 Stars 不一致时，**没有用今天的数字倒推历史，也没有宣称旧数字已通过验证**。当前所有迁移 metric 标为 `verified:false`；发布时保留清晰的历史说明。旧热度不能作为投资、增长或项目成熟度依据。

## 安全和个人数据

静态站没有服务器数据库或模型 API 调用；用户文本经过 HTML 转义。仓库 ID、日期、metric、外键和导入个人数据有格式与长度验证。备份最大 1MB；笔记 2000 字符；合并不删除已有收藏。站内链接不执行用户提供的脚本。

CSP 限制脚本/样式/数据为同源，禁止 object、外部表单和 iframe 嵌入；禁索引只是附加保护，真正私有性依赖 Vercel Authentication。没有关闭访问保护，也没有创建匿名分享链接。

## 验收层次

1. **Node 模型与构建**：22 项回归已在工作容器通过。覆盖历史值、7 期计数、去重、无效日期、外键、metric 类型、备份格式与转义。
2. **本地 Chromium 离线夹具**：20 组检查通过，使用实际源码与构建数据；包括 360/390/768/1440px 下的 6 种页面，导入导出、搜索组合、备注、导航。没有未捕获脚本异常。由于容器禁止 URL 导航，fetch 与 localStorage 使用测试替身；不能冒称这部分验证了真实网络和原生存储。
3. **GitHub Actions 原生浏览器**：提供固定版本 Playwright 测试，使用本机 HTTP 服务、真正 ES Modules 和浏览器 localStorage，并保存实际截图。提交后的成功/失败状态以该提交的 Actions 记录为准，不预先标记通过。
4. **线上发布**：需另核对 Vercel 构建、部署文件与 Authentication 配置；READY 不是端到端验收。当前连接读取保护绕过入口返回 403，不能据此宣称登录后的线上页面已被完整实测，也不会为测试关闭保护。

## 本次不冒充已完成的能力

自动发现和独立核查、AI 日报生成、跨设备云同步、自动 Release 追踪、全部历史上游事实再认证，均不包含在已经实现的功能内。提供独立新期快照导入接口，以后可以接入发布流水线，不把采集任务混进前端。
